# AL scaffolds — generated from approved TGDs

One folder per GAP (`al/GAP-x/`), generated by the assistant **only from a TGD with
status `approved`** (same gate discipline as TGD-from-FGD; the validator enforces
it). The scaffold is the first 30–40% of development: object skeletons, captions in
every client language, event-subscriber signatures, and a test codeunit per TGD
test-plan row — with `// TODO(TGD §n)` markers where the developer implements logic.

## Rules

- Structure: `app.json` (dependencies + id-range from the TGD) + one `.al` file per
  object in TGD §3 + `test/` with one test codeunit mirroring TGD §9.
- The scaffold never invents beyond the TGD: anything the TGD leaves open becomes a
  `// TODO(TGD §…)` or a question back on the TGD, not improvised code.
- **The architect reviews the scaffold diff before a developer starts** — a review,
  not a rewrite. Merges only through the architect (human gate #3 stays).
- Event names/publishers marked "confirm against installed version" in the TGD stay
  marked in code (`// VERIFY:`) — the developer resolves them on the real environment.
- Captions: NL + EN from the terminology glossary; no hardcoded strings.
