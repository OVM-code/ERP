# Workshop briefings — prepared, not improvised (one file per workshop)

Before each requirement workshop the assistant generates a briefing pack from what
is already known: the intake, the scenario catalog for the domains on the agenda,
the industry pack (if any), and the expertise layer. The senior consultant walks in
with hypotheses to confirm instead of blank questions to ask.

## Format — `YYYY-MM-DD-<topic>-briefing.md`

```markdown
# Briefing — workshop <domein(en)>, <datum>

- **Deelnemers verwacht:** <rollen>
- **Domeinen / agenda:** 2 Verkoop, 12 Interfaces
- **Bronnen:** intake.md v<datum>, catalog, pack <naam>, LL-…

## 1. Wat we al weten (uit intake + vorige meetings)
<Feiten met bronverwijzing — niets hervragen wat al vaststaat.>

## 2. Hypothese-scope
<Per relevant scenario uit de catalogus: verwacht in/uit scope + verwachte
invulling, op basis van het klantprofiel en het industry pack. Dit wordt de
werk-coveragematrix van de workshop.>

| Scenario | Hypothese | Te bevestigen met |
|---|---|---|
| BS25.202 | in — standaard, 3 kanalen | vraag 3, 4 |

## 3. Vragen (genummerd — transcript citeert deze nummers)
<Alleen vragen die de hypotheses toetsen of gaten vullen. Batch per thema.
Markeer beslissingsvragen (⚠ scope/geld) apart.>

## 4. Lessen die hier spelen
<LL-/SDR-verwijzingen die dit klantpatroon raken — wat we vorige keer leerden.>

## 5. Na de workshop (zelfde dag)
- [ ] Transcript/notities in inputs/ + REQ-extractie draaien
- [ ] Hypothese-scope bijwerken → coverage.md
- [ ] Open punten → agenda volgende workshop
```

The same-day loop is the point: gaps discovered today are questions next week —
while the client is still in the room — instead of change requests in month six.
