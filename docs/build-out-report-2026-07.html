Control

Every component gets a human review — by design, tracked

Your requirement, made mechanical: the /review-system skill runs a structured review session on any component (briefing → sharp questions → approved diffs only → logged). Coverage is tracked in system/reviews/register.md — 20 components mapped, 0 reviewed so far. That register is the honest number to manage: the methodology is built; it is not yet reviewed.

Review sessions are cheap by construction: the assistant assembles the briefing and the demo example, asks specific closed questions ("does this gate match how you actually triage?"), and only reviewer-approved diffs land. Rejected suggestions are recorded too — that is expertise, and it feeds the lessons layer.
