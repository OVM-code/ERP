Reorganisation

Target operating model — agents draft, humans decide, machines verify

The reorganisation is not "add AI": the repo already has agents authoring. It is a role inversion — human capital moves from producing documents to the two places where it is irreplaceable and billable: the client room, and the review gate. Everything reviewable gets a draft; everything checkable gets a validator; nothing ships ungated.

Role redesign

Senior consultant → decision maker

Stops writing deliverables. Time moves to workshops, argumentation, the four gates (scope, FGD, cutover, delivery) and client relationships. The billable unit becomes the decision, not the document. Target: ≥60% of senior time client-facing (from ~35% typical).

Junior consultant → pipeline operator

Runs the agent pipeline per stage, triages validator output, prepares review packets for seniors. Apprenticeship inverts: juniors learn by reviewing drafts against the knowledge base instead of formatting documents — faster route to judgement.

New: knowledge curator (0.2–0.4 FTE)

Owns the flywheel: industry packs, effort baselines, terminology glossary, lessons-learned promotion, template versions. This is the role that makes project #13 cheaper than project #12 — today that compounding is nobody's job.

Solution architect → gate owner

Owns FGD/TGD approvals and the AL-scaffold review (L05). Also owns the "became standard?" check each release wave — the cheapest customisation is the one you delete because Microsoft shipped it.

Sequence

Roadmap — three horizons, every item builds on what exists

Ordered so that each horizon funds the next. Horizon 1 is pure extension of the current repo — no new infrastructure, mostly templates + one tool each.

Sequencing logic: measurement and reuse first (they compound and de-risk everything else), execution automation second (needs baselines to prove its worth), productised aftercare last (needs reference clients from horizons 1–2).

Do not touch

What the methodology gets right — protect it while scaling

The human gates

FGD approval before TGD, consultant review flags in the manual, scope sign-off. As agent volume grows, the temptation is to soften gates to clear backlog. Don't — widen review capacity instead (that's what the role redesign is for).

Traceability as architecture

Quote §14 → REQ → scenario → plan step → FGD AC → TGD test. This chain is why AI drafting is safe here at all, and it is the audit answer when a client disputes scope. Every new stage must join the chain, never bypass it.

Validators as definition of done

Mechanical checks are what make output model-independent (Sonnet ≈ Opus ≈ Fable on this pipeline). Every new capability in this report ships with its validator rule, or it doesn't ship.

Repo-as-system portability

Plain markdown + stdlib Python + self-contained HTML: no vendor lock, no infrastructure bill, Copilot Studio and Claude run the same instructions. Resist platformising until a leak demands it (only L10's Q&A agent truly does).

This review was produced against the actual repository (every "evidence" line cites a real file). The euro figures are your assumptions × stated formulas — deliberately simple, shown per leak, and meant to be argued with. They are planning-grade, not audit-grade.
